# Клиент iOS: Tor, фон и push (этап после Android MVP)

## Tor на iOS

Orbot на iOS нельзя использовать как системный прокси, поэтому Tor встраивается
в само приложение библиотекой:

- **Tor.framework** (обёртка над libtor) — приложение само запускает локальный
  tor-процесс и поднимает SOCKS5 на 127.0.0.1:9050 внутри своего процесса;
  `Transport.kt`-логика переносится в Swift как есть: весь трафик — через этот
  локальный SOCKS, режим torOnly = true по умолчанию.
- Сервер в режиме onion-сервиса (см. DEPLOY.md режим A) доступен напрямую
  через встроенный tor — домен и TLS не нужны вовсе.
- Добавить проверку при старте: tor не поднялся → приложение не отправляет
  ничего (тот же принцип, что на Android).

Реализация: Swift-модуль `VeilCore` с зависимостями `Tor.framework`
(SPM), `SQLCipher` (через CocoaPods/SPM), `libsignal-ffi` — тот же
протокол, что у Android-ядра, что даёт кросс-платформенную совместимость.

## Фоновый режим (ограничения Apple)

Apple не даёт держать постоянный сокет в фоне. Поведение:

1. Приложение в переднем плане — живое соединение через tor, доставка сразу.
2. Свернуто: WebSocket/конверты работают ~30–170 сек (BGTaskScheduler),
   затем сокет закрывается.
3. Закрыто: работает только push (см. ниже), при открытии — `GET /fetch`
   догоняет очередь с сервера.

Это принципиальное ограничение платформы, не обходится; на Android то же
самое решается foreground service.

## Push: архитектура без утечки метаданных

Принцип: push-сервис никогда не знает, КТО и ОТ КОГО получает сообщение.

- **Свой push-ретранслятор** (тот же VPS или второй): подписка анонимная —
  устройство присылает случайный push-токен-алиас (генерируется на клиенте,
  привязан к APNs-токену), реле конвертов ассоциирует только алиас.
- Содержимое пуша: «0» — одна буква, никакого текста, ID отправителя, юзернейма
  или счётчика. Раскрыть по нему нечего.
- APNs-токен ротируется; соответствие токен↔алиас хранится только на устройстве,
  на реле — только алиас, удаляется вместе с /erase.
- Компромисс, о котором честно: Apple/APNs видит, что устройству доставлен
  пуш от нашего bundle-id и его частоту. Содержимого и адресата — нет.
  Для максимума — push отключаемая опция «tor-only, без push».

## Фоновые задачи

- `BGProcessingTask`: поллинг `GET /fetch` через tor по расписанию (раз в ~1 ч).
- VoIP-звонки: CallKit + PushKit VoIP-пуш (тот же анонимный алиас).
